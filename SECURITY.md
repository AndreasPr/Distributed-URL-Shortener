# Security reporting

For abusive short links, use the application's `/abuse` page and its report flow.
For a suspected vulnerability, use the operator mailbox shown on `/contact` or
`/abuse` when configured. If the site says the mailbox is missing, a private
reporting channel has not been configured; do not post sensitive details publicly.

Do not send credentials, private keys, session tokens, or other users' personal
data. No response-time guarantee, bounty, certification, or public encryption key
is offered. See [the threat model](docs/threat-model.md) and
[security controls and limitations](docs/security.md).
